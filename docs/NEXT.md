## 1. 청한 알림 — 「쉼」 한 글자

헌법이 허락하는 유일한 리텐션 장치인데 아직 만들지 않았다. 침묵 게이트의
기준은 「부르지 않았는데 오는 것만이 알림」이다 — 사용자가 직접 켠 알림은
사용자가 부른 것이다.

- **알림 내용은 「쉼」 한 글자. 그것뿐이다.**
  - 한 글자면 부를 수가 없다. 「사경할 시간입니다」도 「저녁이다」도 결국
    앱이 말을 거는 것이지만, 「쉼」은 명령도 안내도 아니고 한 글자가 놓인
    것이다.
  - 언어를 늘려도 번역할 것이 없다. 영어 rest, 일본어 休. 한 글자 규칙만
    지킨다.
- 사용자가 켜야 켜진다. 기본은 꺼짐.
- 시각은 사용자가 정한다. 하루 한 번까지.
- 끊겨도 아무 일 없다. 며칠 안 열어도 다시 조르지 않는다.
- 알림을 몇 번 받았는지, 눌렀는지 세지 않는다.
- 웹 푸시라 iOS 는 홈 화면에 추가해야 온다. 그 안내를 설정에 한 줄로.

## 2. 코끼리를 부위별로 — 대부분 끝났다(2026-09-17)

가는 동안에도 걸음이 이어지고, 아홉째 정거장(등지)에서는 걸음을 멈추고 흰빛 1 로

코까지 차례로. 값은 사용자가 정한 것(다리 ±5도, 한 걸음 1.8초 등)이 앞서 적은

  먼저 밝아지고 머리 · 다리가 따라오게 하려면 무리마다 흰빛을 조금씩 늦춘다.

도상은 말하지 않는다 — 걷는 것은 말하는 것이 아니다(STATUS 의 확정된 규칙).

## 3. 하루의 때를 그림에 — 끝났다(2026-09-18)

마당의 조감도와 날들의 미륵당 그림에 때의 빛을 한 겹 얹었다. 그림 파일은 건드리지
않는다(§2). 때는 문 셋과 같은 계산(`GateLight`)에서 오고, 화면이 열릴 때 서버가 정한다 —
시간을 재는 스크립트는 없다.

- **문 셋의 네 색을 쓰지 않는다.** 문 셋의 새벽 #EEF2F5 · 밤 #E8ECF2 는 파랑이 빨강보다
  높아 온도 자물쇠에 걸린다. 문 셋의 빛은 「다가오는 빛」이고 마당의 빛은 「해가 있는
  자리」다 — 마당은 제 빛을 갖는다. 넷 다 따뜻한 쪽이고, 밑색을 섞어 만든다.
- 새벽 #DED1B4(옅기 0.3) · 낮 손대지 않음(0) · 저녁 #B47A47(0.42) · 밤 #7E7A72(0.68).
  곱하기로 얹으므로 밤은 빛깔보다 밝기가 내려간다. 값과 옅기는 모두 `:root` 에 있다.
- **미륵이 솟는 장면에는 얹지 않는다** — 그 장면은 그 자체가 빛이다.
- **전각 이름의 대비는 테를 빼고 잰다.** 글자 둘레의 한지빛 테(text-shadow)를 바탕으로
  잡으면 15.15:1 로 높게 나오지만, 테는 바탕이 아니라 글자 둘레다. 원본 조감도에서 이름
  자리의 바탕 픽셀을 재면 밤에 선방 4.61 · 미륵당 5.76 · 마당 5.25 · 문 5.43:1 이다.
  장경각(담 위)은 2.73, 사경실(나무 위)은 2.09 로 낮아, 이 둘은 테가 읽힘을 맡는다 — 밤을
  더 어둡게 하려면 이 둘의 자리나 테를 먼저 손봐야 한다.
- 자물쇠(`daylight_test`): 네 빛이 따뜻한 쪽, 솟는 장면에 빛 없음, 때를 글자로 적는 곳 없음,
  네 빛과 옅기가 모두 `:root` 상수, 땅 위에 놓인 이름 넷이 테 없이도 4.5:1 이상.

## 4. 그림 파일 정리 — 끝났다(2026-09-18)

`app/assets/images/` 가 7.0MB 에서 671KB 로 줄었다. 화면이 늦게 뜨면 어떤 움직임도
살아나지 않는다.

- **쓰지 않는 원본 셋**(`compound_src.png` · `maitreya_src.png` · `four_kings.png`)을
  `docs/sources/` 로 옮겼다. propshaft 는 `app/assets/images/` 를 통째로 실으므로 거기
  있으면 쓰지 않아도 배포에 따라간다.
- **쓰는 그림 일곱을 WebP 로**(품질 90, 맥의 파이썬 Pillow 로 한 번만 바꿔 넣었다 —
  젬도 서버의 도구도 늘리지 않는다). 산수화는 화면에서 뜨는 크기의 두 배에 맞춰 864 →
  768 로 줄였고, 나머지는 이미 그 안이라 픽셀은 그대로다. 바꾸기 전 PNG 는
  `docs/sources/` 에 남겨 두었다.
- **품질은 눈으로 골랐다.** 80 · 85 · 90 을 만들어 확대해 보니 하늘의 띠(banding)는 어디에도
  없었고, 80 · 85 는 한지의 결이 뭉개졌다. 그래서 90.
- **자물쇠**(`images_test`): 합계 690,000 바이트, 아이콘 밖의 PNG 없음, 각 그림이 화면에서
  뜨는 크기 안쪽.
- 코끼리 SVG(53KB)는 그대로다. 걷는 코끼리(앉기)와 흩어지는 코끼리(무위)는 무리마다
  클래스가 닿아야 해서 인라인한다. 장경각 여섯째 장의 서 있는 코끼리 아홉은 그림을
  `<defs>` 에 한 벌만 두고 `<use>` 로 가리킨다. 그 장의 HTML 은 492KB(gzip 152KB)에서
  68KB(gzip 23KB)로 줄었다. 앉기 · 무위의 한 벌도 경로의 소수 자릿수를 줄이면 더 준다.

## 5. 탑신 바탕을 기둥선 따라 사다리꼴로 — 끝났다(2026-10-07)

탑신의 바탕(`.pagoda__wash`)을 층마다 그 층 기둥선의 네 끝점을 이은 사다리꼴로
고쳤다. 아래가 넓고 위가 좁다 — 윗변은 아랫변의 아흔두~아흔다섯 푼이고, 그 비율은
기둥선이 정한다(층마다 기둥의 기울기가 조금씩 다르다).

- 옅기는 **0.04 그대로**다. 사다리꼴이 되었다고 0.10 까지 올렸다가 되돌렸다 — 윗변이
  아랫변의 아흔두~아흔다섯 푼이라 모양이 눈에 잘 띄지 않는데, 그걸 옅기로 밀어 올리는
  것은 순서가 거꾸로다. 모양은 기둥선이 정하게 두고, 옅기는 글씨를 위해 옅게 둔다.
- 비율을 CSS 한 줄로 두는 길(`clip-path: polygon()` 에 `--pagoda-taper` 를 넣는 것)도
  있었지만 고르지 않았다. SVG 도형에 거는 clip-path 의 백분율은 브라우저마다 흔들리고,
  무엇보다 **기둥선을 따라가는 것이 「같은 비율」보다 정확하다**. 그림이 정하게 두었다.
- 자물쇠: 「위가 좁다」는 기능(`test/models/pagoda_test.rb` — 다섯 층 모두 윗변 < 아랫변,
  네 꼭짓점이 기둥선의 끝과 같다), 「0.10」은 결(`copying_form_test`).

## 7. 앉은 코끼리 그림 — 끝났다(2026-10-22)

코끼리는 길가 바위에 앉아 있다(§2, 2026-10-08). 부위 회전만으로는 앉은 자세가 나오지 않아
앉은 그림을 따로 두었다. 손으로 그린 것은 원본과 모양이 달라(머리가 몸에 묻히고 귀가 덩어리)
**원본 픽셀에서 윤곽을 뜬 SVG** 로 바꾸었다 — `docs/drawings/elephant_sitting_traced.svg` 에서
출처 기록(`<metadata>`)만 빼고 `app/assets/images/elephant_sitting.svg` 로 들였다.
선방에 들어설 때 걸어오는 것은 서 있는 그림이고, 바위에 닿으면 **3.2초 교차 페이드**로 앉은
그림이 된다(`--elephant-seat-time`, 두 그림이 같은 곡선으로 엇갈린다). 움직임을 줄이면 바로 바뀐다.
지키는 것은 결 자물쇠 `test/locks/form/elephant_seated_test.rb`.

| | 서 있는 그림 `elephant_parts.svg` | 앉은 그림 `elephant_sitting.svg` |
|---|---|---|
| 틀 | `viewBox 0 0 347 243`, 왼쪽을 본다 | `viewBox 0 0 250 268`, 왼쪽을 본다. 두 그림의 발끝이 같은 바닥선(틀 비율 250/268) |
| 무리 | `body · tail · leg-br · leg-bl · leg-fr · leg-fl · trunk · head · tusk` 아홉 | `body · ear · trunk · tail · tusk` **다섯.** 다리와 머리는 움직이지 않으므로 body 하나에 든다 |
| 축 | 각 무리에 `data-pivot`, CSS 에 `transform-origin` | `data-pivot` 과 `style="transform-origin: …"` 를 파일 안에 박았다. CSS 에 옮기지 않는다 |
| 색 | 변수만(`--e-fill` · `--e-ink` · `--e-tusk` · `--e-fill-far`) | 같은 변수만. 흰빛은 두 그림이 같이 먹는다 |
| 먹선 | stroke | `fill-rule="evenodd"` **면.** path 수는 뜻이 없어 세지 않는다 |
| 뒤척임 | 머리 · 코 · 꼬리 · 다리 넷 · 몸통 | **귀 · 코 · 꼬리만.** 몸통 · 상아는 멎는다. 귀는 머리의 주기를 빌린다 |
| 무게 | 54,066 B | 50,000 B 이하(지금 39,143 B). 바위는 그리지 않는다 |

**아홉째의 코끼리를 눕히는 일은 거뒀다** — 코끼리가 길을 가지 않으므로 아홉째라는 자리가
없다.

## 9. 가입을 여는 날 — 처리방침에 넣을 두 줄

「서버가 국외에 있으면 가입을 열 수 없다」는 자물쇠는 **없다**(2026-10-07 확인). 검사에
나오는 「서울」은 모두 시간대 이야기였다. 있는 것은 `SignupGate`(운영에서 기본 닫힘)와
`STATUS.md` 의 결정(먼저 한국)뿐이다. 그러니 가입을 열 때 할 일은 자물쇠를 푸는 것이
아니라 **처리방침에 두 줄을 넣는 것**이다.

- **수탁자 줄** — 서버 회사(Oracle 또는 카카오)와, 터널을 쓰는 동안은 **Cloudflare**.
  `privacy.trustees` 의 빈 표에 이름과 나라를 적는다. 맡기기 전에 처리위탁 계약서를 받는다.
- **국외 이전 줄** — 개인정보 보호법 **제28조의8**(국외 이전). 근거는 「별도의 동의」이거나
  「계약의 체결·이행을 위한 처리위탁·보관」 등이다. 다만 **어디까지가 국외인지를 먼저
  가려야 한다**: 기록이 서울 리전에 있으면 보관은 국내다. 그래도 조문은 「조회되는 경우를
  포함」하므로, 국외에서 관리 접근이 일어나는 회사(Oracle)와 트래픽이 국외 엣지를 지나는
  Cloudflare 는 따져 봐야 한다. **조문과 실제 경로를 함께 보고 적는다 — 짐작으로 적지 않는다.**
- **백업도 서울로** — 서버를 카카오클라우드 서울로 옮기는 날, 밤 백업도 같은 리전 오브젝트
  스토리지로 옮긴다. 그 뒤 `docs/legal/privacy.md` 국외이전 표에서 GitHub 줄을 지우고 「없음」으로 바꾼다.
- **메일 발송사 후보** — NHN Cloud Email(국내 리전 여부: **확인 필요**) · 네이버클라우드 Outbound Mailer
  (국내 리전 여부: **확인 필요**). 국내 리전이면 privacy.md 국외이전 표의 메일 줄도 지운다.
- **마당은 계정 없이 열린다 — 가입을 열어도 구경하는 길을 막지 않는다.** 그날 약속
  자물쇠로 잠근다(지금 `guest_test` 는 「가입이 열리면 손님의 자리가 없다」로 되어 있다 —
  그 검사를 뒤집어 「가입이 열려도 손님은 본다」로 바꾸는 날이다).
