## 2. M3-1 — 빈 일정

### 2.1 극히 단순하게

날짜별로 한 줄을 적고 지운다. 그것이 전부다.

- **시각을 두지 않는다.** 몇 시 몇 분을 적기 시작하면 이 화면은 달력이
  아니라 일정 관리 도구가 되고, 그때부터 빈 날은 실패로 읽힌다.
- **개수를 세지 않는다.** 「몇 건」이 뜨는 순간 그것은 지표가 된다.
  달력에는 일정이 있는 날에 먹점 하나가 찍힐 뿐, 몇 개인지는 어디에도
  없다.
- **알림이 없다.** 적어 둔 일이 다가와도 앱은 아무 말도 하지 않는다.

### 2.2 숫자의 경계 — 명문화

이 앱에서 화면에 숫자를 두는 **유일한 예외는 달력의 날짜**다.
본질상 불가피하기 때문이며, 그마저 `.date` 안에 가둔다.

| | |
|---|---|
| 허용 | 달력 격자의 날짜 · 하루 화면의 날짜 (모두 `.date` 안) |
| 금지 | 일정 개수 · 배지 · 「n건」 · 달성률 · 비운 날의 수 |

달 이름과 요일 이름은 글자로 적는다(일월·구월 / January·September).
`spirit_test` 가 `.date` 를 걷어낸 뒤 화면에 숫자가 한 자리라도 남으면
깨진다. 사용자가 손으로 적은 말은 검사하지 않는다 — 그것은 사용자의
것이다.

### 2.3 축하하되 비교하지 않는다 (제5조)

| 언제 | 말 |
|---|---|
| 오늘 일정이 없다 | 「오늘은 비어 있다. 잘 비웠다.」 |
| 오늘 일정이 있다 · 낮 | **아무 말도 하지 않는다** |
| 오늘 일정이 있다 · 저녁 | 「바쁜 하루였다. 이제 내려놓아도 된다.」 |

바쁜 날의 말은 빈 날의 말을 뒤집은 것이 아니다. 「잘 비웠다」의 거울은
「잘 비우지 못했다」이겠지만, 그런 말은 이 앱에 없다. 바쁜 날에는 낮
내내 침묵하다가 저녁에야 위로 한마디를 건넬 뿐이다.
`days_flow_test` 가 저녁 문구에 나무라는 말이 섞이지 않았는지 검사한다.

### 2.4 비움 예약

미리 비워 둔 날은 달력에 옅은 원으로 남는다. **비움은 약속이지 목표가
아니다** — 지키지 못해도 아무 일도 일어나지 않는다. 달성률도, 알림도,
되돌아보는 말도 없다.

비운 날의 **아침 첫 화면**에서만 달이 살짝 크게 한 번 숨 쉰다.
같은 아침에 두 번은 숨 쉬지 않는다(SPIRIT 형상 원칙 — 온기는 빈도가
낮을수록 진하다).

### 2.5 데이터

```
Plan                    ← 일정 한 줄
  user
  planned_on:date
  what:string           ← 예순 자
  index [user_id, planned_on]

Clearing                ← 미리 비워 둔 날
  user
  cleared_on:date
  unique index [user_id, cleared_on]
```

`Calendar` 는 값 객체다. 한 달의 격자를 만들고, 각 날에 대해
있음·비움·오늘 세 가지만 말한다. 세는 일은 하지 않는다.

- 어조: **초대이지 등급표가 아니다.** 사용자가 어디쯤 와 있는지
  판정하지 않는다(제3조). 「단계」·「수준」·「진도」 같은 말을 쓰지 않는다.
- 두 문장 이내의 카피 규정은 본문에는 적용하지 않는다 — 여기는 산문이다.
  다만 느낌표와 이모지는 여기서도 없다.
